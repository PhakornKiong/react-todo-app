Goal
-----
Upgrade this repository's dependencies to current safe versions, reduce security and compatibility risk, and produce a small, reviewable set of changes that preserve app behaviour. "Done" means package.json and yarn.lock are updated for all non-breaking (minor/patch) upgrades, CI/build/start succeed locally, and a clear, scoped plan + PRs exist for the remaining major-version upgrades requiring code changes.

Scope
-----
In scope
- Upgrade all dependencies and devDependencies to the latest non-breaking (minor/patch) releases automatically.
- Produce a separate, staged plan for major-version upgrades (React, react-dom, react-scripts, Bootstrap) that require code/work changes.
- Verify the app boots (yarn start), builds (yarn build), and tests (yarn test) after the safe upgrades.

Out of scope
- Applying automatic major-version upgrades that may break runtime behaviour (React 15 -> 16/17/18, react-scripts major upgrades) in this single run.
- Large refactors (rewrite to Vite, migrate to TypeScript) — those are separate projects.

Phases
------
Prerequisites (manual but scripted):
- Node (>=14 recommended) and Yarn installed. This repo uses yarn.lock so we will use yarn.
- Confirm working tree is clean and create a branch: git checkout -b chore/upgrade-dependencies

Phase 1 — Snapshot & safety checks (changes: none)
- Actions:
  1. Save the current package.json and yarn.lock in the branch (commit a snapshot before edits).
  2. Run: yarn --version && node --version && cat package.json
- Tests / verification:
  - Confirm git branch created and commit made.
  - Record current package.json and yarn.lock in the commit.
- Commands:
  - git checkout -b chore/upgrade-dependencies
  - git add package.json yarn.lock || true
  - git commit -m "chore: snapshot before dependency upgrades" --allow-empty

Phase 2 — Automated safe upgrades (non-breaking)
- Goal: move all packages to the latest minor/patch releases only.
- Actions:
  1. Use npm-check-updates (ncu) to update package.json but restrict to non-major changes:
     - npx npm-check-updates -t minor -u
  2. Install updated deps: yarn install
  3. Run app checks: yarn build && yarn test && (yarn start manual smoke test)
- Files changed:
  - package.json (versions updated)
  - yarn.lock (regenerated)
- Tests / verification:
  - yarn install exits cleanly.
  - yarn build completes without error.
  - yarn test returns success (if tests exist; non-zero is a failure).
  - Spot-check app manually by running yarn start and navigating to the app (smoke test): UI loads, basic interactions work (add/remove todos).
- Commands (sequence):
  - npx npm-check-updates -t minor -u
  - yarn install --frozen-lockfile || yarn install
  - yarn build
  - yarn test || true
  - (manually) yarn start  # verify smoke tests
- Commit:
  - git add package.json yarn.lock
  - git commit -m "chore: upgrade dependencies (minor/patch)" \
    -m "Automated non-breaking upgrades applied with npm-check-updates. Build+tests verified locally."

Phase 3 — Identify and plan major upgrades (changes: plan files only)
- Goal: enumerate packages that require major-version upgrades and record per-package migration steps.
- Actions:
  1. Run: npx npm-check-updates -t newest (or run `npx npm-check-updates` without -t) to list major upgrades.
  2. Produce a short migration plan per major package (React/react-dom, react-scripts, bootstrap) including the expected code changes and tests.
  3. Create follow-up PRs, one per major upgrade (or group closely-related upgrades) to keep blast radius small.
- Files changed:
  - .artifacts/plans/issue-cb403931-1058-4f18-9e61-ccf37edd3189-major-upgrades.md (new)
- Verification:
  - The major-upgrades plan lists each package, target version, migration steps, and verification commands.

Phase 4 — (Optional) Execute major upgrades in separate PRs
- Approach: For each major package, open a dedicated branch/PR and perform the upgrade + code fixes + tests.
- Example order (recommended):
  1. react & react-dom: 15.x -> 16.14 -> 17 -> 18 (stop at the chosen target). Apply prop-types import fixes, check deprecated lifecycle methods.
  2. react-scripts: upgrade to 4.x/5.x (ensure Node version compatibility).
  3. bootstrap: 3.x -> 4.x/5.x (update markup/classes if needed).
- Verification per PR:
  - yarn install
  - yarn build
  - yarn test
  - manual smoke test (yarn start)
  - run ESLint / static checks if present
- Commit messages: Explain why, list migration steps, and reference this plan.

Phase 5 — Finalize and cleanup
- Actions:
  - When all safe upgrades and chosen major upgrades are merged, delete upgrade branches.
  - Update README if Node/Yarn version requirements changed.
- Verification:
  - CI passes (if available).
  - App behavior confirmed in staging or local environment.

Risks
-----
- Major-version upgrades (React, react-scripts) will likely require code changes (PropTypes, lifecycle methods, build config). Risk: broken UI or build failures.
- react-scripts major upgrade may require Node version changes or dev-dependency changes (bump Node requirement).
- Some transitive dependency changes could introduce subtle runtime behavior differences.
- Automated non-major upgrades may still surface deprecation warnings; test coverage is limited (no automated UI tests present).

Mitigations / early checks
- Do safe (non-major) upgrades first and verify build/start before attempting majors.
- Make small, focused PRs for each major change with manual smoke tests.
- Keep a snapshot commit (Phase 1) so rollbacks are trivial.
